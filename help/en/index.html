pcmonitor – Help

Open help using F1 or Help → Help. Refresh using View → Refresh inventory (F5). Select a section on the left; search and filter occupancy on the right.

RAM slots are read from lshw when accessible to the normal user. Only RAM banks explicitly reported empty are marked empty. Physical M.2/USB/SATA positions are not inferred from logical devices.

TXT export: File → Export results. Reports include every section regardless of filters. MAC/IP/SSID require explicit selection. Available serial numbers appear in device details and are exported only with personal-data opt-in. Device events are optional.

Collection is read-only and installs nothing. start.sh is unprivileged. start-admin.sh invokes pkexec at most once per elevated inventory. A fixed isolated helper reads lshw and dmidecode --type 17 directly; the window stays unprivileged. Each source has its own status and timestamp. Denial never triggers a second request. Cancellation and closing stop helper queries; concurrent inventories are blocked. Each tool has a 20-second limit; the entire request including authentication has a 120-second limit. Details, export and monitoring never request privileges. Cancelled queries leave unavailable values unknown. Missing tools and timeouts appear under System information. Events are polled every 3 seconds; brief events may be missed. Monitor resolution and refresh rate require XRandR and may be unavailable under Wayland.

Since 0.2.0 the Type column separates slots, components, hubs, hardware adapters, virtual interfaces, drives and partitions. Occupancy is only asserted for supported slots/connectors. Empty RAM banks show Empty once.

RAM: suspicious source values remain unverified; no overflow repair or conversion between MHz and MT/s is guessed. Additional dmidecode values require explicit units and a unique slot locator. Present and online CPUs are shown separately.

Monitor modes require valid, unique EDID mapping. Disconnected does not prove Empty. Optional nvidia-smi supplies NVIDIA memory mapped by PCI address. Sensors show the device path.

LAN shows carrier and speed; Wi-Fi shows signal and bitrates. Audio shows active ports and default devices. BlueZ supplies Bluetooth devices and connection events. Unavailable interfaces remain visibly unavailable; no settings are changed.

Export: Bluetooth aliases and user-defined audio descriptions also require personal-data opt-in. MAC/IP patterns in names and events are otherwise redacted. Events begin with the first successful query per source; brief changes and query gaps may be missed.

Since 0.2.1 LAN events distinguish operational state from physical adapter carrier changes. Virtual adapters have no cable status. Occupancy filters keep components without applicable occupancy visible. Sensors include available device and model names and retain their unique path. Export redaction cannot guarantee removal of arbitrary private text or serial numbers embedded in external device names. Review exports before sharing.

Device details (0.3.0): Only verified occupied and associated monitor connectors, RAM banks and PCIe slots show an Occupied button. Click once or focus using Tab and press Enter/Space. Empty, Unknown and rows without occupancy cannot open details. The separate window has a device heading and Close button.

Monitor details: manufacturer code/model, connector/graphics card, verified XRandR mapping, separate active and supported modes, approximate EDID dimensions/diagonal and available serial number. Without unique XRandR mapping the active mode remains unknown. Base EDID timings may provide only an incomplete mode list. Unavailable EDID fields are marked unknown.

Monitor and PCIe occupancy is checked in the background before opening and while a detail window remains open; RAM uses only the last confirmed capture. Removal, replacement or an unverifiable state marks the view outdated, stops further detail queries and removes stale details from export. Values show their inventory timestamp. F5 collects a new inventory. Brief changes and identical replacements between polls may be missed. Without EDID a replacement on the same monitor connector cannot be reliably detected.

RAM details use the confirmed occupied bank in the session snapshot; no new RAM query or additional pkexec. USB components and drives are not treated as occupied physical sockets. Detail serial numbers enter TXT exports only with personal-data opt-in; review exports before sharing.

RAM session cache (0.3.1): the last successful capture is shown with date/time and query mode. This is not continuous RAM hotplug verification. Data remains only in memory for this program session. F5 captures again in the configured query mode. A failed or restricted refresh retains confirmed data with its original timestamp and marks it as an older capture; a notice reports the failure. Inaccessible data does not prove removal.

A newly confirmed empty slot or different module marks the old window superseded. The same confirmed module receives updated data and timestamp together. Exports include the actual capture time, mode and refresh status for older RAM data too. Serial numbers require personal-data opt-in. The session cache is discarded on exit; no new persistent cache file is created. This does not repair or invent RAM speed values.

RAM firmware values (0.3.2): explicitly choosing elevated startup and F5 in that mode also reads dmidecode --type 17 with elevated privileges. Normal mode never elevates. Detail clicks and open RAM windows use only the session snapshot. The GUI remains unprivileged.

Configured data rate (firmware) and reported module speed (firmware) are separate values matched to a unique exact slot locator. MHz and MT/s are not equated; no lshw overflow repair. Details and exports show source, query mode and actual firmware capture time. Limited SMBIOS support remains a visible source notice; values are not live clock measurements.

Missing tools, denial/cancellation, timeout, incomplete values and association conflicts have separate source statuses. Successful lshw module data remains available. Previously confirmed firmware values for the same module retain their original time and an older-data notice if refresh fails. A replacement module does not inherit old speed values. Serial numbers still require personal export opt-in.

If the elevated query fails, Help → Log shows its failure stage and return code without raw hardware data. Run ./start-admin.sh --diagnose-admin for a single diagnostic request. At most one privilege request; provide the output for investigation.

RAM overview: manufacturer, model, capacity and configured data rate (firmware). Missing valid configured values are unknown. Older firmware values retain their original timestamp and an age notice. Discarded lshw raw values remain in details only. Reported module speed, source status, time and SMBIOS warning remain separate in details and export; these are not live clock measurements.
